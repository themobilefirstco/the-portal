# Code and security review — October 31, 2026

The Portal remains a source preview. This review strengthens its engine and onboarding; it does not establish that a fresh real Google account or an unattended hardware room passes the live acceptance checklist.

## Scope and method

Reviewed controller routes and command sequencing, Calendar/OAuth and Meet polling, scheduling and departure decisions, browser ownership/recovery, credential persistence, installation/rollback, setup UI, tests, documentation and CI. Inspected the tracked source and available Git history for credentials and known private deployment identifiers. Added regression tests for the concrete failures below and exercised the suite on hosted macOS runners.

The README animation is an original illustrated workflow using synthetic content. It contains no screen recording, real meeting, account, attendee, credential or production room URL. Its generation script is included; Pillow is a development-only dependency for regenerating the asset.

## Findings fixed

| Priority | Finding and consequence | Fix and evidence |
| --- | --- | --- |
| High | A synchronous polling exception could leave `busy` pointing to an already settled promise, preventing subsequent refreshes. | Yield before executing the reader; regression proves the lock clears and the next read recovers. |
| High | A failed Keychain write could leave Google tokens accepted in memory even though authorization was not durably saved. | Persist before publishing new tokens/client state; injected persistence failure cannot produce a connected room. |
| High | Failed deployment verification followed by a failed stop could delete files belonging to a still-running service. | Preserve both the running installation and previous backup when stopping fails; regression verifies both copies survive. Manual recovery remains necessary. |
| High | A known Calendar failure could still permit a new automatic call using the previous snapshot for up to its freshness window. | Explicit sync errors block new scheduled/drop-in starts while retaining existing call deadlines; regression covers error, recovery and a future-dated snapshot. |
| Medium | Four-second status refreshes overwrote unsaved setup fields after focus moved to another field. | Dirty forms survive refresh and failed submission, clearing only after successful save. Real Chrome fixture tests Unicode room naming through the synthetic HTTP server. |
| Medium | Decoding each HTTP chunk separately could corrupt a Unicode character split across chunks. | Collect bounded bytes, then decode once. Tests split a multilingual payload at every byte boundary. Both local and agent APIs share the parser. |
| Medium | Local endpoints accepted ambiguous JSON body shapes and content-type prefixes. | Require a JSON object and a proper JSON content type; test malformed/non-object input, byte limits and content-type rejection. |
| Medium | Changing room identity did not explicitly invalidate guest-monitor snapshots and backoff. | Clear old guest-monitor state and advance its generation when changing accounts, alongside Calendar invalidation. |

An Intel CI run exposed a temporary-profile cleanup race after the headless Chrome close command. Shutdown now awaits process/pipe closure, with a regression proving that a command acknowledgement is insufficient; temporary-directory cleanup uses bounded filesystem retries.

Additional regressions verify single-flight refresh/disconnect behavior, rejection of expired OAuth state, unverified email, missing Google subject and account changes during pending authorization. Existing tests continue to cover manual-leave suppression, host admission, participant uncertainty, bounded retries, request replay, token rotation and preserving dashboard/unrelated tabs. HTTP integration now also tests hostile Host headers and disabled OAuth in synthetic mode.

## Credential and confidentiality audit

- Gitleaks **8.30.1**, downloaded from its official release with SHA-256 verification, reported **zero findings** in the tracked tree and all available Git revisions inspected during the review. Output is fully redacted; reports stay outside the repository.
- A separate search found no known original room email, private host address, original login/password literal or personal machine path in those revisions.
- Reviewed tracked file names and content: no OAuth JSON downloads, production state, browser profiles, private research transcripts, credential files or runtime archives are included. Public company attribution and the contributor's GitHub noreply commit identity are intentional metadata.
- Added checksum-pinned full-history Gitleaks scanning to CI and enabled GitHub native secret scanning, push protection and private vulnerability reporting.
- These checks are bounded evidence, not a guarantee against every unknown secret format or confidential value. Git-ignored local material and other directories on a developer's machine are outside this repository audit. Never upload them with an issue or PR.

## QA results and reproducibility

Run from the repository root on macOS with Chrome installed:

```bash
bash scripts/bootstrap.sh
runtime/node scripts/check.mjs
runtime/node scripts/test.mjs
```

The expanded suite contains **102 tests: 99 logic/HTTP tests and three real headless Chrome fixtures**. The browser fixtures use synthetic Meet markup and a synthetic local setup server; they do not contact Google or exercise real camera/microphone hardware. The reviewed code passed all 102 tests with zero skips on both architectures in [this hosted run](https://github.com/themobilefirstco/the-portal/actions/runs/41240654254). See the [Actions results](https://github.com/themobilefirstco/the-portal/actions) for the exact commit and architecture. The final published commit must have successful Apple Silicon, Intel and credential-scan jobs.

The local managed development environment passes the 99-test logic/HTTP suite but cannot launch temporary Chrome. That restriction is recorded as a local full-suite failure, not hidden by skipping browser tests; hosted macOS runs provide browser evidence. Source syntax, documentation links, executable launchers, version consistency and credential patterns are checked separately. The GIF's four phases were visually inspected.

## Remaining risks and recommended order

| Priority | Remaining work | Acceptance criterion |
| --- | --- | --- |
| Release gate | Fresh-account onboarding and real Keychain access are not end-to-end verified. Source-built helper identity/prompts need testing after rebuild and installation path changes. | A new macOS user follows the public guide with a personal account and a Workspace account; reconnect, locked Keychain and upgrade are tested without editing code. |
| High | Browser operations and some setup/Meet API work still run inside the shared command queue. Per-request timeouts do not bound the total wait across several requests/pages. | Inject slow/hung dependencies and prove Leave/deadline processing remains responsive; separate network preparation from generation-checked state commits. |
| High | Installer activity checking and stopping are separate operations. Concurrent installers, a meeting starting during staging, and verifying the exact new service instance need stronger coordination. | An authenticated maintenance lease prevents new joins before stopping; exclusive install lock, instance identity checks and disposable-user upgrade/reboot tests pass. |
| High | Real Meet DOM changes, media permissions and device delivery remain external dependencies. An on-screen “on” control is not proof that a remote guest receives audio/video. | Complete the [live acceptance checklist](acceptance.md), including interrupted calls, two-way media, device reconnection, 100 cycles and the multi-day pilot. |
| Medium | State/log persistence and abrupt-process recovery need longer operational testing. The controller is concentrated in a large module. | Test disk-full/corrupt-state recovery and log retention; extract an injected controller state machine before expanding UI or provider scope. |
| Medium | Source distribution has no notarized native app, signed updates or stable signed helper distribution. | Define signing/release ownership, verify upgrade trust and rollback, then build accessible native onboarding. |

Do not resolve these gaps by weakening account checks, disabling security prompts, publishing debugging ports, or declaring hardware success from synthetic tests. The [contribution roadmap](roadmap.md) turns them into focused work that contributors can review and validate.
